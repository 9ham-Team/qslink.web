# 审核消息中转程序开发 Prompt

以下内容可直接交给开发 agent：

---

请实现一个独立的 QSLink 审核消息中转服务。QSLink 仅发送审核文本；本服务负责接收、可靠保存、转发到企业微信群，并按本服务配置 @ 审核人员。不修改 QSLink，不访问其数据库，也不实现审核操作。

默认使用 Node.js 24、TypeScript、SQLite 持久化队列，提供 Dockerfile、Compose、环境变量示例、README 和自动化测试。如目标仓库有既定技术栈，遵循现有技术栈实现同等行为。交付可以直接运行的程序，不仅是设计方案。

## QSLink 接收协议（必须兼容）

- 提供 `POST /hooks/qslink/:token`，使用服务端配置的高强度随机令牌鉴权；上游只能配置 URL，因此不要求额外自定义请求头。每个推送实例使用自己的唯一令牌和 URL，并映射到本服务预设的转发目标。
- `Content-Type: application/json`，UTF-8，消息体如下：

```json
{
  "msgtype": "text",
  "text": {
    "content": "QSLink 卡片待审核\n提交类型：新卡片\n卡片：我的 QSL 卡片\n呼号：BG7XXX\n提交者：张三\n卡片 ID：c_example\n审核入口：https://qsl.example.com/admin?tab=cards"
  }
}
```

- `content` 是不超过 2048 个 UTF-8 字节的非空文本。只接受 `msgtype=text`，按白名单提取 `text.content`；上游不发送收件人、企业微信 URL、@ 列表或事件 ID。不要依赖解析中文正文来决定收件人或鉴权。
- 可靠入队成功后尽快返回 HTTP 200 和 `{"errcode":0}`，应远小于上游 5 秒超时。此响应表示本服务已持久化接收，不代表群消息已送达。入队失败返回非 2xx 和非零 errcode，不要虚报成功。
- 上游在数据库提交后发送一次，无自动重试。不能通过重复请求 QSLink 来补发，不能承诺端到端恰好一次。后续合法编辑可能产生相同正文，不要仅凭正文或卡片 ID 去重而丢弃消息。
- 限制请求体大小（例如 16 KiB），拒绝非法 JSON、错误类型、空正文和超长正文。未知令牌返回统一的无敏感信息错误。不要要求请求体包含并不存在的结构化事件字段。

## 转发与 @ 配置

- 每个接收实例在服务端配置企业微信官方 Webhook URL 和 `atUserIds` 数组。支持多实例、各自唯一令牌；无后台 UI 要求，可使用持久挂载的私有 JSON 配置文件，并提供只有占位符的示例。
- `atUserIds` 填企业微信 userid，支持 `@all`；清理空白、忽略空项并去重。留空不 @。配置更新重启生效即可。
- 将收到的正文作为文本消息转发，在本服务中添加 `text.mentioned_list`：

```json
{
  "msgtype": "text",
  "text": {
    "content": "收到的审核消息正文",
    "mentioned_list": ["zhangsan", "lisi"]
  }
}
```

- @ 所有人时为 `["@all"]`，不 @ 时省略 `mentioned_list`。只使用本服务配置的 @ 列表，忽略请求体中夹带的任何 @ 字段。中和正文中的 `<@userid>` 扩展语法，防止通过正文添加额外 @。
- 企业微信目标必须是预先配置的官方 HTTPS 机器人发送地址，不接受请求指定转发 URL，不跟随重定向，不关闭 TLS 校验。
- 检查企业微信 HTTP 状态和返回 JSON，只有 `errcode=0` 算转发成功。请求设置明确超时，失败在本服务持久化队列中进行有限次指数退避重试；达到上限保留失败记录，提供本地 CLI 人工重试，不公开无鉴权重试接口。
- 为每个企业微信目标实施限速，初始保守设置为每分钟 15 条、平滑发送，并在实现时核对企业微信当前官方限额。不要通过并发 worker 绕过目标限速。
- worker 重启后恢复未完成任务。网络结果不明确时重试可能造成重复群消息，需在 README 如实说明；实例令牌、目标和 @ 配置变更对已有队列任务的行为必须明确。

## 运行、安全与验收

- 数据库及队列放入独立持久卷；优雅退出停止接收新任务并处理 worker 状态，避免并发重复领取。配置文件和数据库不提交 Git。
- 日志使用内部任务 ID，不输出接收令牌、完整请求 URL、企业微信 URL 密钥、消息正文或完整配置；代理访问日志也要脱敏含令牌的路径。状态接口只返回必要健康信息，不包含队列正文或密钥。
- 提供健康检查；管理命令可查看队列统计、按内部任务 ID 重试失败记录。生产入口使用 HTTPS，并具备基本请求限流。
- 测试覆盖：正常接收/持久化确认、无效令牌、JSON 和长度校验、多个实例路由、配置 @ 和 @all、忽略上游 @ 注入、企业微信非零 errcode、HTTP 失败、超时、重试上限、限速、进程重启恢复。使用本地 mock 企业微信服务，不能在自动化测试中发送真实群消息。
- README 写明配置格式和启动命令，展示 QSLink 仅需设置 `QSL_REVIEW_WEBHOOK_URL=https://你的中转域名/hooks/qslink/你的令牌`；QSLink 不需要配置 @ 人员。
- 实现结束报告文件、启动方式、实际测试结果及未验证事项。真实群联调、发送测试消息和部署需要单独授权；不要自动向真实群发消息。
